Running HEP-Genesis-Agent from the command line.

Every feature of the desktop app is scriptable: quick tool-backed chats, autonomous research runs with reports, MCP tool servers, custom LLM endpoints, and HPC dispatch. This guide documents the CLI as exercised in practice during alpha testing (v0.3.x).

Basics

Install and invoke

The CLI is a Python wheel (requires Python 3.10+). The binary is hep-genesis-agent.

Install

pip install --upgrade hep_genesis-0.3.16-py3-none-any.whl[all]

Grab the wheel from the releases page, verify against SHA256SUMS.txt, and install with the [all] extra (report LaTeX support, arXiv tooling). The CLI installs into your active Python environment as hep-genesis-agent.

First commands

hep-genesis-agent --help
hep-genesis-agent --list-projects
hep-genesis-agent --version

Everything is organized around projects (a directory with chats, research runs, reports, and provenance) and chats (a named conversation inside a project, default default).

# minimal quick-mode call (no tools):
hep-genesis-agent --quick "What is 2+2?" --servers none --project demo

# two chat modes share one backend:
#   quick   — the model calls tools directly, conversation-style
#   research— plans, runs worker directions, critiques, writes a report
Quick mode

Tool-backed chat

Quick mode answers one question (or a follow-up in the same chat) using any connected MCP servers.

hep-genesis-agent --quick "compute the relic density of a 1.1 TeV higgsino" \
    --servers command:/path/to/serve-idm.sh \
    --project dark-matter --chat idm

Key flags

--chat NAME — named conversation; reusing a name keeps context, so follow-ups work.
--servers SPEC — which MCP servers to attach (repeatable).
--max-rounds N — cap tool-calling rounds (default 30).
--temperature X — sampling temperature (default 0.0).
--report — write the PDF report of the chat after answering.

Follow-ups keep context

# turn 1
hep-genesis-agent --quick "list the emulators you have" \
    --project qcd --servers module:hep_genesis.domain.mcp_server
# turn 2 — same chat, remembers turn 1
hep-genesis-agent --quick "now plot P(k) for the first one" \
    --project qcd --servers module:hep_genesis.domain.mcp_server
Research mode

Autonomous multi-step research

Research mode plans directions, runs them (optionally in parallel), critiques its own findings, and writes a LaTeX/PDF report.

hep-genesis-agent "Survey recent arXiv work on sterile-neutrino dark matter and BBN constraints" \
    --project sterile-dm \
    --servers module:hep_genesis.domain.mcp_server \
    --max-waves 2 --workers 3 --max-tool-calls 60 --wall-clock 30

Budget flags

--max-waves — rounds of directions (default 4).
--workers — parallel directions (default 5).
--max-tool-calls — total tool budget (default 400).
--wall-clock — minutes (default 120).

Phases

survey → plan → critic-plan → wave(s) → critic-wave → replan → report. Each wave posts findings to a board with claims and evidence; critics can close or block directions.

Outputs

reports/<timestamp>/ — report.pdf, supplement.pdf, transcript.pdf (+ .tex sources). research/<chat>/board.json — machine-readable findings. Run events in runs/<run-id>/events.jsonl.

hep-genesis-agent --board --project sterile-dm        # view findings/critiques
hep-genesis-agent --list-runs --project sterile-dm   # list runs
hep-genesis-agent --show-run RUN_ID --project sterile-dm
hep-genesis-agent --report --project sterile-dm      # (re)generate the PDF
MCP servers

Connecting tool servers

Four spec forms; --servers is repeatable and accepts a comma-separated list.

# module: a Python module inside the app (bundled servers)
--servers module:hep_genesis.domain.mcp_server

# command: launch any executable that speaks MCP over stdio (most robust)
--servers command:/abs/path/serve-my-server.sh
--servers command:/abs/path/serve.sh?name=my-server        # custom display name

# url: hosted HTTP server
--servers url:https://example.edu/mcp

# path or git URL: pip-installs the server repo (see caveat below)
--servers /path/to/my-mcp-repo
--servers https://github.com/org/my-mcp-server
Practical caveat (v0.3.16): path/git specs expect the repo to define a [project.scripts] console entry point; servers that ship as python -m mcp_server (a common pattern, including several HEP-KE servers) fail to launch with FileNotFoundError. Use command: with a small wrapper script until that is fixed (issue #1).

Wrapper recipe

#!/bin/bash
cd /path/to/my-mcp-repo || exit 1
exec .venv/bin/python -m mcp_server "$@"

Point --servers command: at this. Per-server venvs avoid dependency collisions (e.g. an emulator pinned to scipy<1.11).

Bundled server

module:hep_genesis.domain.mcp_server ("hep-research-aid") ships with the wheel: arXiv search/download, table loading and statistics, histograms, file I/O, skills, memory, report writing, and local/HPC dispatch (set_dispatch local|polaris|perlmutter).

LLM backends

Custom endpoints and per-stage models

Any OpenAI-compatible endpoint works; configuration is via environment variables.

export LLM_URL="https://your-gateway.example.org/v1"
export LLM_MODEL="claude-opus-5-5"          # or gpt-5.6-luna@openai, ...
export LLM_API_KEY="..."                     # from your provider

# optional: a different model per research stage
export LLM_SURVEY_MODEL="claude-haiku-5-5"
export LLM_WORKER_MODEL="claude-opus-5-5"
export LLM_CRITIC_MODEL="claude-opus-5-5"
export LLM_REPORT_MODEL="claude-opus-5-5"

Verified endpoints

Tested against the MAG gateway (mag.genesis.americansciencecloud.org) with gpt-5.6-luna@openai and claude-opus-5-5 — both drive tool calls correctly. Per-stage overrides are read as LLM_<STAGE>_URL/_MODEL/_API_KEY.

Token accounting

Every invocation ends with a usage line, e.g. Tokens: 12K in (7.0K cached) · 369 out · 3 calls. Research runs break it down per stage (worker / survey / report / critic / plan) — useful for cost tracking on metered gateways.

Run control

Steer, pause, resume, continue

Long research runs can be supervised and revived from another terminal.

hep-genesis-agent --steer RUN_ID "also compare against the Planck value" --project sterile-dm
hep-genesis-agent --pause RUN_ID --project sterile-dm
hep-genesis-agent --resume RUN_ID --project sterile-dm      # or: query "continue"
hep-genesis-agent --stop RUN_ID --project sterile-dm        # stop and write the report
hep-genesis-agent --continue d-04 --project sterile-dm --servers ...   # one open direction

Coding tasks

--coding enables the last-resort run_coding_task tool (pi harness); all code is saved under the project. Useful for one-off data wrangling a tool can't express.

Workspace: skills & memory

hep-genesis-agent --list-skills      # workspace skills
# in chat: "Remember this lesson: ..." → remember tool
#          "Load the skill named X"   → load_skill tool

Skills are skills/*.md files whose YAML frontmatter contains name: and description: (files without a name: are skipped silently). Memory accumulates in MEMORY.md and persists across sessions. Workspace dir is configurable via HEP_WORKSPACE_DIR; projects via HEP_PROJECTS_DIR.

Recipes

Worked examples from alpha testing

Commands below were actually run against v0.3.16 with real MCP servers attached.

Physics query + explanation

hep-genesis-agent --quick \
  "Compute the DW production fraction of a 1 keV sterile
   neutrino with sin^2(2theta)=1e-8, and its radiative
   lifetime in seconds." \
  --servers command:.../serve-sbbn.sh \
  --project dm --chat sbbn

The agent called predict_sterile_nu, then explained the τ ∝ m−5 scaling — correct against the tool's own numbers.

Multi-server comparison

hep-genesis-agent --quick \
  "What is D/H for N_eff=3.044 (sterile-nu server) and
   the relic density of a 1 TeV higgsino (inelastic-dm
   server)? Which does Planck favor?" \
  --servers command:.../serve-sbbn.sh \
  --servers command:.../serve-idm.sh \
  --project dm --chat multi

Two servers, one conversation, correct routing of each sub-question to the right tool.

Bounded literature survey

hep-genesis-agent \
  "Survey 2024-2026 arXiv papers on sterile-neutrino DM
   and BBN. Which mass-mixing regions remain viable?" \
  --project sterile-dm \
  --servers module:hep_genesis.domain.mcp_server \
  --max-waves 1 --workers 2 --max-tool-calls 25 \
  --wall-clock 15

Downloaded 8 papers, produced 10 board findings and an honest PDF report (it flagged its own full-text extraction failure rather than inventing numbers).

Data analysis in one line

hep-genesis-agent --quick \
  "Generate 1000 Gaussian(5, 2) samples via run_test_job,
   then compute statistics and a histogram." \
  --servers module:hep_genesis.domain.mcp_server \
  --project stats --chat dom

Chained tool calls across the bundled server's data pipeline.

Environment variables: LLM_URL · LLM_MODEL · LLM_API_KEY · HEP_PROJECTS_DIR · HEP_WORKSPACE_DIR · per-stage LLM_{SURVEY,PLAN,WORKER,CRITIC,REPORT}_*. Full test log: ~/hep-genesis-testing/ (alpha-testing workspace).
